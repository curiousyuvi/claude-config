Published-KB caching architecture agreed with Konrad on 2026-08-07 (Slack). His "Option A" (Worker builds pages from R2 files) with one substitution: R2 files carry **pre-rendered, pre-sanitized HTML parts**, not raw data. The route Worker is a byte splicer with zero layout knowledge; the backend remains the only renderer (it must anyway: preview + knowledge panel).

Artifacts per KB under `kb/{kbId}/`: `settings.json` (mode, verbatim CSP string), `template/{locale}.html` (chrome with `<!--kb:slot:head|nav|body-->` markers), `nav/{locale}.html`, `pages/{locale}/{slug}.json` `{v, parts:{head,body}, cardRefs}`, `nodemeta/{nodeId}.json` `{v, cardHtml}` (cards spliced at read time via `<!--kb:card:{id}-->` regions with baked fallback). Splicing = exact string substitution on marker comments, no HTML parsing (protects the [[kb-prose-prewrap-invariant]] pre-wrap byte invariant). `stitchKbPage()` (~50 lines) lives in packages/shared with exactly three consumers: Worker, backend origin-fallback, preview (preview = production compose on draft parts, so drift is structurally impossible). CI conformance test runs the real Worker bundle under @cloudflare/vitest-pool-workers asserting byte-equality with backend compose against the golden fixtures.

Compatibility rule: pages may over-provide parts; templates never over-demand (write producers first, consumers second). Design changes = data re-bakes + purge, not Worker deploys. ETag = hash of artifact version stamps. KbEventsWorkerService becomes the single bake+purge site (write R2 then purge, outbox retries, coalesced prefixes ≤30/call, reconciler vs Postgres).

Settled decisions: settings-file staleness on public→private flip ACCEPTED (mandatory mitigations: no SWR on settings object, short max-age, synchronous purge on gate/visibility change); any gate ⇒ Worker authorizes against origin every request, gated responses never enter shared cache; CDN base URL treated as fixed, asset URLs baked; search stays origin. Open nit: Konrad said "backend worker can build the whole html" — template+fragments chosen (keeps theme change to one file); whole-page files are the fallback simplification, confirm before taking it.

Phasing (Konrad: "add cache slightly after"): (1) backend-only refactor to parts+stitch, golden tests byte-identical, no Cloudflare; (2) outbox writes artifacts to R2 + reconciler; (3) Worker serves public KBs, origin fallback; (4) gates, custom domains (blocked on verifying purge works on Cloudflare-for-SaaS hostnames), analytics beacon, re-bake tooling.

**SLICE 3 Worker built 2026-08-08** (`apps/kb-edge`, 21 tests green under real workerd, NOT deployed, `"routes": []` so deploying intercepts nothing). Gotchas that cost real time: (1) `@cloudflare/vitest-pool-workers` 0.8.x bundles a Sept-2025 workerd with **no `enable_ctx_exports` flag**; must use **0.20.x**, which needs **vitest ^4.1** (repo root is 4.0.18 — kb-edge carries its own), dropped the `/config` export, and is configured as a **Vite plugin** `cloudflareTest({wrangler:{configPath}})`, not `defineWorkersConfig`. (2) `enable_ctx_exports` became default 2025-11-17 — specifying it on a later compat date is a hard startup error. (3) **`ctx.exports.X.fetch(req, {props})` silently delivers `props={}`** — the docs' cache example is wrong/outdated; the working form is **`ctx.exports.X({props}).fetch(req)`** (configure the binding, then call). Symptom was a silent origin fallback because `kbId` was undefined. (4) Do NOT re-declare bindings in `miniflare:{r2Buckets:[...]}` alongside wrangler.jsonc — backs them with a different store so test and Worker see different objects. (5) `wrangler types` generates `worker-configuration.d.ts` (gitignored); tsconfig `types` = `@cloudflare/vitest-pool-workers/types`.
