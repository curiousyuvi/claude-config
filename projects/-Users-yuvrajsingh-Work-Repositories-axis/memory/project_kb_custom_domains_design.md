**2026-07-21 — PROD routing FIXED via a Cloudflare edge Worker (branch `ys/feat/kb-edge-worker`). This is the crux: CF-for-SaaS CANNOT reach a Railway origin without a Worker.** Root cause chain (all verified vs CF + Railway docs): (1) CF-for-SaaS forwards `Host` **+ SNI = the customer's custom hostname** to the origin (NOT the fallback-origin name); (2) **Railway routes strictly by Host** and 404s ("train has not arrived") any host not registered on a service — arbitrary customer domains can't be registered; (3) Railway **fronts its edge with Cloudflare**, so a proxied CNAME `proxy-fallback.helplydocs.com → *.up.railway.app` is a cross-account CNAME → **CF error 1014 "CNAME Cross-User Banned"** — so NO DNS-record fallback origin can reach Railway; (4) Railway **overwrites `x-forwarded-host`** (and hides the client IP) — so the original host can't ride XFH. The errors appear in sequence as you fix each: fallback-origin-missing → Railway 404 → 1014. **Only fix = a Worker doing an outbound `fetch`** (not a CNAME): host `*`+path `*` route on `helplydocs.com`, rewrite `Host`→Railway origin URL, carry original host in `x-original-host`, client IP in `x-original-client-ip`, auth with `x-edge-secret`. Built `apps/kb-edge` (`forward.ts` pure `planForward` + `index.ts`; wrangler.toml `*/*` route — NB wrangler+SaaS route bug #3662, may need dashboard). Backend: `publicHost(headers, edgeSecret)` + new `edgeClientIp` read the edge headers ONLY when `x-edge-secret` matches `kbPublic.edgeSecret` (`KB_EDGE_SECRET` env); app.ts + kb-reader.middleware pass it; `KbCustomHostRegistry` STAYS (isKbHost still uses it — KV plan DROPPED per user). Konrad's friendly CNAME: target is now `${kbSlug}.customers.helplydocs.com` (`KB_CUSTOM_DOMAIN_CNAME_TARGET` = the BASE, code prepends slugNorm), frozen at connect (cosmetic; wildcard catches any prefix; buildDnsRecords PRESERVES routing on updates). INVARIANT: never put a literal `*/*` inside a JS `/** */` block comment (biome closes the comment at `*/`). Ops handoff (Konrad): deploy Worker, set `RAILWAY_ORIGIN_URL` + `wrangler secret put KB_EDGE_SECRET`, add same `KB_EDGE_SECRET` op-ref to `.env.production` (left as a comment — a bad op ref breaks boot), confirm the `*/*` route. **Provider decision: Cloudflare for SaaS (Custom Hostnames)** — Konrad's suggestion, confirmed. Origin-agnostic (only the control zone e.g. `helply-kb.com` must be a CF zone; NestJS/Fastify app stays put). Customer CNAMEs `docs.acme.com` → our CNAME target → CF terminates TLS at edge → proxies to our **fallback origin**, preserving original `Host`. Use **DCV Delegation** (one-time `_acme-challenge` CNAME) for hands-free cert renewal. **Poll** CF `GET /zones/{zone}/custom_hostnames/{id}` for `status`/`ssl.status` (no reliable hostname webhook on non-Enterprise; SSL-cert-event webhook exists via Notifications as fast-path). Pricing: 100 free, $0.10/host/mo, 50k PAYG cap. brandssl.io = fallback alt.

**Scope decisions (Yuvraj):** support **subdomain + apex**. Apex needs customer-on-Cloudflare (CNAME flattening) OR CF **Enterprise** (Apex Proxying/BYOIP) — apex target value is config-driven; CF plan is a Konrad/ops dependency. **Opt-in 301** subdomain→customdomain redirect (wire existing fake `SubdomainRedirectionCard`); off by default; canonical/OG always point to custom domain when live. One custom domain per KB for v1.

**Hostname parsing = Public Suffix List, NOT dot-counting.** Must support arbitrary subdomain depth (`docs.help.acme.com`) AND multi-part public suffixes (`acme.co.uk`, `example.com.au`, `foo.github.io`). Dot-counting is wrong (`acme.co.uk`=2 dots but apex; `docs.acme.com`=2 dots but subdomain). Use `tldts` (preferred) / `psl` to split `{subdomain, domain, publicSuffix}`; `isApex = registrable domain with empty subdomain`. Apex/PSL distinction ONLY drives which DNS record we instruct (apex→A/flatten, else→CNAME) — CF treats the hostname opaquely so any depth works as a CNAME. instantdocs' hand-rolled `getDomainNameInfo` + `secondLevelTlds` list is the thing NOT to copy; replace with PSL.
