apps/web uses TanStack Router **file-based** routing; `src/routeTree.gen.ts` is generated by the `@tanstack/router-plugin/vite` plugin at Vite startup — there is **no standalone `tsr`/router CLI binary** installed. After adding/moving/removing a route file, `createFileRoute('/...')` fails typecheck until the tree is regenerated.

Regenerate without a full build by briefly booting the dev server: `cd apps/web && pnpm exec vite --host 127.0.0.1 --port <free>` in the background, poll `src/routeTree.gen.ts` for the new route id, then kill it (it writes the tree within ~2s of start). Nested paths under a leaf route need a directory (`routes/.../trash/index.tsx` + `trash/$type.$id.tsx`), not a sibling `trash.tsx`.

Gotcha: macOS zsh has **no `timeout`** command — don't wrap commands in it. Also: the `shared/` package has **no build script** — backend/web resolve its types via TS path mapping directly, so editing `packages/shared` needs no rebuild before typecheck.
