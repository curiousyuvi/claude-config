Building a comment feature for KB article/collection/home page (dashboard/editor context only; never in public reader). Requirements: open/resolved state, @mentions, emoji reactions, text-selection-anchored comments on the two PlateJS surfaces (article + custom homepage; collection has no editor → page-level only), realtime, rich-text input (Cmd+B/I). UI is pixel-accurate to Figma node 223-2430 (384px right rail, Open/Resolved segmented tabs, 14px cards w/ 20px avatars, pill reaction chips 2px 12px/28px with blue `#EFF6FF`/`#60A5FA` active, `#16A34A` unread badge on header button, Edit/Resolve/Delete/Reopen context menus).

**Reuse map (≈85% reuse):**
- **Anchoring** = `@platejs/comment@^53` (NOT yet installed; adds a `comment_<threadId>` leaf mark on selected text; thread data lives OUTSIDE the editor value). Add a `CommentKit` to `apps/web/src/features/knowledge-base/components/editor/plate-editor-kit.tsx` (`kbEditorPlugins`); add "Add comment" button to `kb-floating-toolbar-kit.tsx`. INVARIANT (verified): comment mark is INERT in publish — `static-components.ts` `kbNodeComponents` whitelist has no `comment` key, and `sanitize-kb-html.ts` drops `<span>`/non-`kb-*` classes; so the mark can live in draft content JSON safely. Composer = small Plate editor reusing basic-marks subset.
- **Realtime** = Ably LiveSync outbox (NO new infra). Add `KB_COMMENT_CHANGED` + payload + guard + channel helper to `packages/shared/src/realtime.ts`; add payload to `ably-realtime-outbox.service.ts` union; add ONE additive token capability line in `realtime.service.ts` `buildRealtimeTokenParams`. Publisher clones `mention-realtime.publisher.ts` (agent channel) + `note-updated.publisher.ts` (node channel). Frontend bridge clones `note-reaction-realtime-bridge.tsx` (reactions=in-cache patch) + `mentions-realtime-bridge.tsx` (created/resolved=debounced invalidate). Reuse `consumer-utils.ts` verbatim.
- **Reactions** = new `kb_comment_reactions` (1:1 clone of `note-reaction.entity.ts` + `note-reaction-operations.service.ts` + `note-reaction-summary.loader.ts`, LWW watermark via `countAndStamp()`); frontend reuses `@/shared/emoji` picker (emoji-mart already a dep) + lifts `ticket-workspace/lib/note-reactions.ts` (optimistic/LWW). `@IsSingleEmoji` validator reused verbatim.
- **Comment entity** clones `contact-note.entity.ts` shape (author Agent set-null, `body` jsonb + `bodyPlain`).

**New backend (in `apps/backend/src/modules/knowledge-base/`, layered DDD — NOT a new top-level module):**
- Entities `kb-comment.entity.ts` (table `kb_comments`: baseProperties, uuidv7 PK, author Agent set-null, body jsonb+bodyPlain, `status` open/resolved enum, resolvedAt/By, **locale** column, 3 nullable anchor FKs article/collection/knowledgeBase + hand-added CHECK exactly-one, `anchorMark` jsonb for article/home text anchor, self-ref parentComment for replies, soft-delete deletedAt), `kb-comment-reaction.entity.ts`, `kb-comment-mention.entity.ts` (readAt for unread). Register in `knowledge-base.module.ts` forFeature → `pnpm --filter backend db:entities` → generate migration (hand-edit CHECK) → migration:up.
- Services clone `article.service.ts`; controller clones `article.controller.ts` (thin, `@OrgId()`+`@CurrentAgent()`); DTOs class-validator (clone `article.dto.ts`); response mappers separate files. Barrel exports only `KnowledgeBaseModule`.
- Enums `KbCommentStatus` as-const in `packages/shared/src/schemas/kb-authoring.schema.ts`, re-export from `src/entities/enums.ts`.

**New frontend:** `apps/web/src/features/knowledge-base/components/comments/` (rail, thread, composer, reactions, realtime-bridge) + `api/comments.ts` + extend `api/query-options.ts` + `lib/kb-comment-reactions.ts`. Query-options factories only, <300 lines/file, server-side pagination, TanStack Query (not Zustand). Do NOT export from KB barrel. Closest frontend analogs: `ticket-workspace` note-reactions + `features/mentions` bridge.

**LOCKED DECISIONS (2026-07-24):** (1) Locale = node-level comments that store authoring locale; text highlight renders only on matching-locale content. (2) Mentions = KB-local realtime notify + unread indicator; do NOT touch global `note_mentions` inbox. (3) Homepage anchors to `KnowledgeBase` singleton (+ locale), not `kb_homepage_variant`. (4) Realtime = per-node KB channel `org:{orgId}:kb:{...}` with additive token capability. (5) Orphaned text anchors (edited/deleted text) stay shown in panel like resolved (mark authoritative). Build end-to-end then review; nothing committed w/o permission.

**STATUS (implemented, uncommitted; migration APPLIED locally):** Whole feature BUILT + web/backend typecheck + biome clean + 12 web unit tests pass. Migration `Migration20260727025908.ts` (3 tables + FKs + hand-added `CHECK (NOT (article_id IS NOT NULL AND collection_id IS NOT NULL))`) applied via migration:up. Also required `pnpm --filter backend db:objects` (creates `ably_realtime_outbox` — the realtime publisher writes to it inside the create txn, so a missing table rolls back the whole comment insert).

**ANCHORING PIVOT (critical — learned the hard way):** text-anchored comments are QUOTE-BASED, NOT editor-mark-based. `@platejs/comment` is REMOVED (unused dep left in package.json). Applying a `comment`/`comment_draft` leaf mark via `setNodes(..., {split:true})` inside THIS multi-plugin KB editor creates an empty `{text:""}` split leaf that a render-time `useEditorSelector` can't path-resolve → "Unable to find the path for Slate node" crash, AND the mark autosaved → persisted corruption crashing on load. Two failed attempts (deferred stored-range; then the reference draft-flow) BOTH crashed. Resolution: the floating "Comment" button (`useSelectionQuote`) captures only the selected text; the comment stores `anchorQuote` and the card shows it (border-left quote block) — no editor mutation, no highlight, no click-to-focus. `stripCommentMarks(initialContent)` in kb-article-editor-shell.tsx cleans any legacy comment marks on load so corrupted articles recover. Registering `@platejs/comment` also caused a SECOND crash: the shared link-toolbar reads `usePluginOption({key:KEYS.comment},'activeId')` → OPTION_UNDEFINED once the plugin exists without that option (fixed then mooted by removing the plugin). FOLLOW-UP: re-add a live highlight later via Slate DECORATIONS (ephemeral, no doc mutation) — verify in a sandbox, not blind.

Panel renders OUTSIDE `<Plate>` as a right rail; provider (`KbCommentsProvider`, controlled `open`, `supportsAnchoring`) wraps editor+panel in ArticlePane/CollectionPane (kb-node-view) + KbHomeView custom mode. Existing placeholder `<HeaderIcon label="Comments">` in kb-article-header.tsx was the wire point; added to kb-collection-header + KbHomeHeader. Mention combobox = shared InlineCombobox + `@platejs/mention` getMentionOnSelectItem(editor,{key,text}), agents from `@/api/agents` fetchAllAgents. Reaction pills = native emoji glyphs. REMAINING: sandbox visual verification + PR screenshots (bin/sandbox).
