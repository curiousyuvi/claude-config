User approved (2026-11-09 ~21:40 IST) building ALL of this in the SAME PR as the model config, branch `ys/feat/capture-agent-models` (local commits 0fe2d975d models+cache, d31bf4ebc gpt-6-luna actor + two-breakpoint cache fix; NOT pushed). User rule: general fixes only, no case-specific prompt hacks. Push/PR only after the new work + an eval; user OKed commit/push/PR for this PR.

Why: r18 articles were right per section but wrong as a whole. Billing: survey note said Upgrade is in the account menu (it is in the sidebar trial box); draft copied it, planner asked for the menu, agent pictured it, validator passed per shot; agent saw the truth but could only record/skip. Configure Sharing: planner can't see what existing pictures show (images reach it with no content), so it added a redundant hover shot next to a human picture; new shot also off-style (dark human pics vs light app) and showed leftover "Untitled Article" samples.

Design (build order: 0, 2, 3, 1):
0. Leftover samples: survey `markScreen` (survey-agent.ts) must refuse when the page is this run's sample (SampleEdits.isSample on current URL / trail start); refusal says mark the page where a new item is made instead. Fix the existing refusal text that tells the agent "reopen what you made, then mark it" (root cause: trail restarts on navigation, so a reopened sample looks clean). One-off: clear saved screens on the Helply/InstantDocs connections (local now, prod at redraft time); no name heuristics.
2. Planner sees existing pictures: image scan (imageScanSchema: appScreen, screen, controls; cached per asset) runs before plan (today parallel in article-screenshots.service run()); our own pictures use validator `screen` + recipe target. Image blocks in planner input say what they show. Rule "step that already has an image" generalises to "a step whose screen and control a nearby picture already shows". Model: planner terra medium.
3. Final review: one call over the finished article in order, every picture as small preview marked new/existing, plus survey notes. Structured out: new pictures to remove (+reason), contradicted sentences. May remove only this run's new pictures, only when another picture shows the same screen+control or the picture shows what the text doesn't describe; never rewrites text; contradictions go to the correction path (item 1) if unused, else shown on the gap. Model gpt-6.1-terra medium, new subfeature + key AI_APP_CAPTURE_REVIEW_MODEL (register in ai-features.ts). ~$0.02/article.
1. Wrong-step report: new capture tool `report_wrong_step(intent, elements)`; evidence = labels of listed elements as the page listed them (not model words); counts as a skip otherwise. After the run, ONE correction round: section drafter (terra medium) rewrites only those steps from the evidence, then plan+capture only changed steps; correction appended to gap field notes. Orchestration lives around GapScreenshotService.addScreenshots / ArticleScreenshotsService.illustrate.
Then eval (same 4 gaps: Chats, billing on Helply; password links, HTML embed on InstantDocs) and the pending prod redraft of Helply+InstantDocs gaps after merge (see [[project-local-prod-snapshot-workflow]]).
Also found: shared markTrailingCacheBreakpoint (copilot, background agent) marks only the new end, so OpenAI cache reads likely miss there too; outside this PR, report to user.
