Built 2026-09-02 on branch `ys/feat/realtime-article-editing` (PR #1385, reshaped 2026-09-05 after review). Plate's recommended path is `YjsPlugin` + Hocuspocus/WebRTC; we bind with **`@slate-yjs/core` directly** in our own `KbYjsPlugin` (`apps/web/src/features/knowledge-base/lib/collab/kb-yjs-plugin.ts`) and transport over a **custom Ably provider** (`lib/collab/ably-yjs-provider.ts`) because Ably token auth, channel leases, presence and CSP already exist and a Hocuspocus WS server on Railway would need sticky routing or a Redis extension. `@platejs/yjs` was dropped: it statically imports `@hocuspocus/provider`, `y-webrtc`, `y-indexeddb`, only wires sync callbacks for providers it constructs itself, and forced writes to `_isSynced/_isConnected`.

**Why/how it hangs together:**
- Channel `org:{orgId}:kbcollab:{anchorType}:{id}:{locale}`; token grants `publish` ONLY on `kbcollab:*` (clients must never publish on `kb:*` event channels). Wire: `u` update, `q` state vector, `a` awareness; chunked above 32 KB as `c:<kind>:<id>:<i>:<n>`.
- `KbYjsPlugin`: `createPlatePlugin({ key, options: { session, synced }, render: { afterEditable: RemoteCursorOverlay }, extendEditor })` — `extendEditor` is a CONFIG PROPERTY in Plate v53, not a fluent method. `withYjs(editor, sharedRoot, { autoConnect: false })` → `withCursors` → `withYHistory`. The shell seeds, `YjsEditor.connect`s, `editor.tf.init({ value: null })` with `skipInitialization: true`, then `provider.connect()`. `RemoteCursorOverlay` needs an explicit return type or the overlay↔plugin type cycle makes the plugin `unknown`. `slate` must be a direct web dep for the `Editor` type (pin to Plate's version, 0.124.1).
- Persistence = existing autosave + `collabState` (base64 `Y.encodeStateAsUpdate`) → `bytea` on `kb_article_variants` and `kb_homepage_variants` (migration `Migration20260902142020`). Joiner applies stored state BEFORE connecting; any non-collab `content` writer nulls `collabState` (article.service, homepage upsert, translation worker, import); editors re-seed via `seedSharedRootIfEmpty` (deterministic clientID hashed from guid+content).
- Homepage upsert contract: `version: number | null`; `null` = collaborative save, skip the OCC check. Never infer concurrency mode from whether `collabState` is attached.
- **Save wiring lives in the shell**: in collab mode `provider.onLocalUpdate` calls `onContentChange(editor.children)` and Plate `onChange` is ignored; editors keep a single stage-and-schedule path and only add `collabState: collab?.encodeState()` to the save body. Shell renders the skeleton while `collab === undefined`.
- `KbCollabUser` must be a `type` alias, not an `interface` (slate-yjs cursor data bound is `Record<string, unknown>`).
- Non-body realtime: `kb_node.changed` (`KbNodeChangeAction` updated/published/unpublished/review_changed) via per-anchor helpers in `kb-node-realtime.publisher.ts`; payload has **no actor field** (own-tab skip uses `clientInstanceId`; a null actor reads as "system" and disables the skip). Whether peers must hear about a save is ONE pure rule, `peersMustRefetch({ meta, dirtyBefore, dirtyAfter, approvalDropped })` in `article-dirty.util.ts`, fed by `applyDraft` / `applyVariantChanges` returning `{ meta, body }`. `kb_tree.changed` is published once by `KbEventsWorkerService` for `TREE_EVENTS` and owns tree shape; the node bridge invalidates the tree only for `updated`.
- **Two bugs found only by a two-tab headless probe (2026-09-02), both silent:** (1) React StrictMode's double effect run destroyed the provider, removing doc/awareness listeners and nulling local awareness state (y-protocols `setLocalStateField` is a no-op on null), so nothing was ever published. Fix: provider listeners live for the session, `disconnect` restores local awareness state, session built in an effect (`undefined` = pending). (2) **Ably rejects above 50 msgs/s per channel** (`channel.maxRate`); a dropped `u` strands every later update on the receiver. Fix: merge updates per 100ms with retry-on-reject, throttle awareness to 200ms. Probe pattern: login at inbox.helply.localhost → `/seed-organization/kb/<kb>/<article>`, two browser contexts, type in A, read B's editor text; redo it before claiming collab works.
- **Local-dev caveat:** everything except Yjs body sync rides `ably_realtime_outbox`, invisible locally until the Ably Postgres connector tunnel is set up (wiki `ably-realtime-db-setup.md`: full `postgres://` URL, alphanumeric password on `ably_realtime`, SSL disable).
- Translation-variant editor (`KbArticleVariantEditor`) is NOT collaborative yet — shell supports `collab` prop, so wiring it is small.

**How to apply:** touch collab only through the provider/hook/plugin; never give clients publish on `kb:*`; keep `collabState` nulling in every new backend `content` writer; route any new "tell peers?" decision through `peersMustRefetch`. Verify visually with two browsers on the same article (user does the looking).
